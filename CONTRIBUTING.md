# Contributing — ResQ Project Report

## GitFlow recomendado

- `main`: versión estable / entregable.
- `develop`: integración del trabajo.
- `feature/<tema>`: trabajo por sección o artefacto.
- `release/<version>`: preparación de una entrega.
- `hotfix/<tema>`: correcciones urgentes sobre una versión estable.

Ejemplos:
- `feature/chapter-01-startup-profile`
- `feature/chapter-02-interviews`
- `feature/chapter-04-c4-architecture`
- `feature/chapter-05-ui-design`
- `feature/chapter-06-sprint-1-evidence`

## Conventional Commits

Ejemplos:
- `docs(chapter1): add startup profile`
- `docs(chapter2): add interview analysis`
- `docs(chapter4): add context diagram`
- `docs(chapter5): add landing page wireframes`
- `docs(chapter6): document sprint 1 evidence`
- `fix(report): correct section numbering`
- `refactor(assets): reorganize chapter images`

## Regla de colaboración

Todos los integrantes deben realizar aportes reales y commits propios al Project Report.
Los commits y cambios deben ser coherentes con el Registro de Versiones y con
Project Report Collaboration Insights.
